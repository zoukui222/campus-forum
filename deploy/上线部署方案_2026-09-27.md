- **腾讯云官方 FAQ** 原文：*"若域名不解析到腾讯云中国境内云服务器、轻量应用服务器等云资源，**仅通过服务器公网 IP 直接访问测试，可暂不备案**"*；同一文档另载：*"托管于中国境内服务器的网站或 APP 需要完成备案。**不论设置哪个端口都能被监测到**。"*
  来源：https://cloud.tencent.com/document/product/243/19630
- **阿里云官方 FAQ** 原文：*"当域名解析指向中国内地的服务器并开通 Web 服务时，需进行 ICP 备案。若解析指向境外服务器（如中国香港），则**无需 ICP 备案**"*；备案本身不收费，但需购买支持备案的服务器。
  来源：https://help.aliyun.com/zh/icp-filing/basic-icp-service/product-overview/faq-about-icp-filing-applications-in-different-scenarios
- ⚠️ **冲突提示**：网上流传"不使用 80/443 端口就不需要备案"的说法（如百度云某文章），与腾讯云官方"不论哪个端口都能被监测到"的表述**矛盾**。备案是云厂商在执行的，因此**以云厂商官方口径为准**，不要采信二手说法。

## 三、选定方案

**大陆轻量应用服务器（2核2G）+ 公网 IP 直连 + 暂不备案 + Docker Compose 部署**

理由：

1. **成本最低**：38–99 元/年，一次下单就能用。
2. **无需等待备案**：IP 直连属于腾讯云官方认可的"测试"用法，买完当天即可上线。
3. **贴近真实生产**：自己在 Linux 上跑 MySQL、Nginx 反向代理、容器编排，面试时可讲的内容比"部署到托管平台"扎实得多。
4. **可平滑升级**：以后需要域名，再去备案（免费，约 7–20 个工作日），备案通过后把 `.env` 里的 `SERVICE_IP` 换成域名、Nginx 监听改为 80/443 即可。

代价：对外呈现的是 `http://<公网IP>:8080` 形式，不如域名美观。

## 四、部署步骤

### 1. 购买服务器

- 地域：选离自己/面试官近的大陆地域（如杭州、北京）
- 镜像：**Ubuntu 22.04 或 24.04**
- 配置：2核2G 起，40G 系统盘

### 2. 配置安全组（放行端口）

| 端口 | 用途 |
| --- | --- |
| 22 | SSH 登录 |
| 8080 | **对外访问网站（必须）** |

### 3. 安装 Docker 与 Compose（Ubuntu）

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo systemctl enable --now docker
sudo usermod -aG docker $USER && newgrp docker
docker compose version
```

### 4. 上传项目到服务器

在**本地**执行（用 scp 或 git clone 均可；推荐 git clone，后续更新方便）：

```bash
ssh root@<公网IP> "git clone https://github.com/<你的用户名>/campus-forum.git /opt/campus-forum"
```

### 5. 本地构建前端并上传 dist

小内存服务器不适合装 Node 构建前端，**在本地构建后上传**：

```bash
cd frontend && npm run build          # 产出 frontend/dist
scp -r frontend/dist root@<公网IP>:/opt/campus-forum/frontend/
```

### 6. 配置环境变量

```bash
cd /opt/campus-forum
cp deploy/.env.example .env
vi .env      # 填写 MYSQL_ROOT_PASSWORD 与 SERVICE_IP（SERVICE_IP 不含端口！）
```

### 7. 启动

```bash
docker compose up -d --build
docker compose ps          # 三个容器都应为 running/healthy
docker compose logs -f backend
```

### 8. 验证

```bash
curl -I http://<公网IP>:8080/                       # 应 200，返回前端首页
curl -s http://<公网IP>:8080/api/public/board      # 应返回板块 JSON
```

浏览器打开 `http://<公网IP>:8080/`，注册账号、发帖、上传图片，确认图片能正常显示。

## 五、部署时容易踩的坑

1. **对外端口必须与 `server.port` 一致（都是 8080）**
   `UploadService` 用 `SERVICE_IP + ":" + server.port` 拼图片访问地址。若 Nginx 对外监听 80 而 `server.port` 是 8080，上传的图片 URL 会指向一个不可访问的端口，图片全裂。
2. **前端是 history 路由**（`createWebHistory()`），Nginx 必须配 `try_files $uri $uri/ /index.html` 回退，否则刷新 `/post/1` 直接 404。已在 `deploy/nginx.conf` 配好。
3. **上传目录必须挂 volume**，否则 `docker compose up --build` 重建容器后用户上传的图片全部丢失。已挂 `upload-data:/app/file`。
4. **MySQL 初始化脚本只在数据卷为空时执行一次**。后续改表结构需手动导入：`docker compose exec -T mysql mysql -uroot -p campus_forum < xxx.sql`。
5. **2G 内存跑 Maven 构建可能 OOM**。构建阶段建议加 2G swap：
   `sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile`
6. **拉取 Docker Hub 镜像慢**：可配置镜像加速器，或在本地 `docker build` 后 `docker save`/`docker load` 传过去。
7. **线上务必改掉演示账号密码**。`backend/sql/campus_forum.sql` 中的演示数据带的是开发期密码，公开部署前应逐一重置（尤其是 `ADMIN` 角色账号）。
8. **`SERVICE_IP` 不要带端口**，只填 `http://<公网IP>`；填成 `http://ip:8080` 会拼出 `http://ip:8080:8080/...`。
